# Bounded offscreen glyph rendering

This experimental path prepares coverage masks from Eris's three bundled fonts
and composites them with a custom integer WGSL kernel over Vulkan. The CPU never
paints or uploads the final GPU destination. Rectangles, source images and glyphs
retain display-list order through separate compute passes. This is an offscreen
checker; the native browser still uses its existing painter and presenter.

`browser_adapter::plan_display_list_with_fonts` and `plan_snapshot_with_fonts`
are separate from the original rectangle/image APIs. The original bridge still
refuses Text and retains its sixteen frozen cases. Rounded geometry and opacity
groups remain whole-frame refusals in either API. Preparation refusal discards the
entire tentative plan; a GPU/device/readback error remains an error. The new
checker expects all its font cases to be admitted and treats refusal as failure.

## Font preparation and placement

The additive `graphics::text_masks::Session` uses a private frame cache, independent
of the original CPU font cache. Monospace takes precedence over bold; italic is
the existing synthetic row shear. Masks use the original eighth-pixel size
quantization, while kerning and advance use the unquantized size. Each occurrence
retains its exact signed row origins, computed after document/fixed offsets and
before GPU submission. Glyph commands use these absolute integer coordinates
and the current clip; they do not apply offsets a second time.

The shader gathers one coverage byte for each output pixel. It first truncates
`color_alpha * coverage / 255`, then applies the existing rounded integer RGB
source-over calculation. Distinct rows and columns cannot write the same pixel
within a glyph dispatch; overlapping glyphs remain separate ordered passes.
The existing rectangle and image shaders retain their bytes.

The font provider accepts only the immutable bundled DejaVu faces. Pinned
`ab_glyph` outline construction allocates its own curve vector before returning
bounds, and its rasterizer allocates infallible scratch storage. The session
limits cold requests before outline construction and validates dimensions,
coverage storage and scratch size before rasterization. These checks do not make
those dependency allocations fallible or bound every curve operation. Downloaded
fonts, system font discovery, shaping and font fallback are outside this path.

## Bounds

The original limits remain: 320×240 target, 256 commands, 32 typed scopes,
1 MiB of explicit GPU buffers and four million dispatch invocations. The explicit
buffer total includes the output, readback, uniform slots, source pixels,
coverage words, image lookup tables and glyph row origins.

New ceilings are 4,096 complete input scalars per frame, 32,768 UTF-8 bytes per
text command, 65,536 text bytes per frame, 256 cold mask requests including empty
masks, 1,024 pixels per mask axis, 262,144 cells per mask, 262,144 aggregate coverage
bytes, and 65,536 row-origin entries. Images and mask records share the original
256-source ceiling. Row tables have at most 256 records and 1,024 entries each.
Expanded commands, including scopes and empty glyph occurrences, share the
256-command ceiling.

A pre-raster callback accounts conservative prospective GPU storage and row
work before mask allocation. It charges all supplied unique image bytes and a
viewport-sized lookup allowance per image command, so admission can refuse a
frame even when a tighter final plan would fit. Coverage stays in the bounded
session and is packed once into the plan. Metadata, coverage, row staging and
font-library scratch remain separate CPU allocations; the 1 MiB figure is not
a total process or driver memory bound.

The CPU completion bound is `nontext_commands * frame_area` plus
`max(mask_area, 1)` for every reached mask occurrence, including repeated and
off-clip cells. It must fit the unchanged CPU painter allowance. Hidden text is
still subject to complete input and structural checks. Cache warmth cannot relax
admission. Limits refuse whole frames; they never truncate the submitted text.

## Separate evidence populations

The frozen inputs in [glyph-fixtures](glyph-fixtures/README.md) contain twelve
literal-mask cases with 223 independently calculated pixels. Their `.rgb24`
files encode three bytes per oracle pixel; GPU readbacks use four-byte packed RGB
words with a zero high byte. The fourteen direct font display lists instead use
full images generated by the preserved CPU implementation at `5ad2cfd`. These
344,064-byte `.rgb` baselines use little-endian `0x00RRGGBB` words and are explicitly
reference-derived. Matching them is regression evidence, not independent proof
of font coverage correctness.

The glyph checker compares current cold/warm CPU images to those parent baselines
and requires identical cold/warm GPU plans before initializing Vulkan. It launches
no page workers. A separate subreaper supervises each checker process and verifies
cleanup before the host advances to another adapter. This direct-font checkpoint
does not add real-worker text capture or native-window glyph drawing.
The subsequent [worker-text suite](WORKER_TEXT.md) exercises the same adapter
with actual HTML worker snapshots; native-window glyph drawing remains open.

Build and perform the CPU comparison without GPU initialization:

```sh
cargo build --locked --manifest-path tools/vulkan-raster-probe/Cargo.toml \
  --features browser-bridge --bin eris-vulkan-glyph-check
tools/vulkan-raster-probe/target/debug/eris-vulkan-glyph-check --cpu-check \
  --baselines tools/vulkan-raster-probe/glyph-fixtures/parent-baselines
```

All 26 cases pass on the NVIDIA, AMD and software Vulkan adapters: 344,956
compared bytes per adapter, 1,034,868 total. Both Rust 1.88 and 1.98 pass the CPU
checker, strict Clippy and the relevant Rust tests. All eighteen new Python
protocol/host tests pass. Offline Naga validation checks the new shader; original
rectangle and image shader bytes are unchanged. The
[validation record](evidence/host-glyphs.json) preserves raw results and initial
compile/test failures, including their corrections.

Run the supervised GPU comparison with an installed loader:

```sh
python3 tools/vulkan-raster-probe/run_glyph_host.py --allow-experimental-gpu \
  --binary tools/vulkan-raster-probe/target/debug/eris-vulkan-glyph-check \
  --output glyph-host-1 \
  --baselines tools/vulkan-raster-probe/glyph-fixtures/parent-baselines \
  --loader-directory /path/to/installed/loader
```

No browser compatibility, production security or Chromium performance target
follows from this bounded experiment.
