# Glyph fixture and immutable-parent reference preparation

This directory contains two distinct test populations. Neither font rasterization nor a browser, renderer, planner, compiler, worker or GPU has been executed during preparation. The old 30 probe and 16 bridge cases are unchanged.

* `literal-fixtures.json`: 12 independent small-mask cases, 223 pixels. Input coverage bytes and positions are explicit. The full packed-RGB arrays and 669 RGB24 bytes in `literal-rgb/*.rgb24` come from standalone integer/Fraction arithmetic in `prepare.py`. The alpha multiplication truncates first; each RGB source-over operation rounds separately with +127. No mask is derived from a font or candidate.
* `font-inventory.json`: 14 direct display lists, 86,016 pixels per future reference pass. These inputs bind all three audited bundled fonts, ordinary and synthetic italic placement, kerned/monospace text, absent scalars versus empty outlines, Unicode/composites, original-size metrics versus quantized raster size, subpixel boundaries and ordered clip/fixed/image overlap. There are no font output pixels yet. Future files are **reference-derived immutable-parent CPU baselines**, not independent font coverage goldens.

`literal_inventory.rs` constructs only bounded owned data and direct expected literals. `font_inventory.rs` constructs only bounded direct lists using public `eris::graphics` types. `verify_transcription.py` parses their restricted Rust literal syntax without executing Rust and checks every name, scalar (f32 bit pattern where appropriate), command, string, image key, source/row table and independent expected pixel against the JSON. It also rechecks all 91 archived parent inputs. `transcription-review.json` records that data-only check.

The literal suite includes separate semantic declarations for 19 invalid/cap inputs and three accepted cap plans. These declarations are not extra rendered pixel fixtures. Refusal categories identify the selected contract, not candidate error wording. Unused source and row metadata must validate. Reached Glyph IDs and row-height equality validate before alpha-zero/clip omission. Only 0x0 is a valid empty mask. Full i32 positions are valid and clipped with wide arithmetic. Nonempty zero coverage retains a draw, even though it cannot change output. Individual and aggregate source/table/operation limits are unchanged from the agreed contract.

`reference-parent` is extracted from `parent-source.tar`, an exact git archive of commit `5ad2cfd3582f92f8368a0a0fa2fd3bb7dd7af2f0` Cargo files, source and assets. `parent-source-freeze.json` binds the archive and all 91 original files. The only added file beneath it is `src/bin/glyph-reference.rs`; no archived file was changed. That harness imports the shared `font_inventory.rs` and uses the parent's existing `Fonts`, `Canvas` and display-list API. It requires a new output directory, fresh Fonts per case, and exact equality between cold and warm renders. Exhaustion or a nonzero target high byte fails the run. It writes one `<name>.rgb` per case, **four bytes per pixel, little-endian packed 0x00RRGGBB with no header** (344,064 bytes total). The `.rgb` suffix does not denote RGB24 here; the explicit encoding in the inventory and output records is authoritative. External provenance must bind the built harness and these future output bytes before candidate use.

The unexecuted harness can later be built with the parent Cargo.lock and explicit `--bin glyph-reference`, and run with `--output-dir NEW_DIRECTORY`. No build command was run in this preparation. A rustup-mediated formatting attempt could not create its toolchain temporary file; the already-installed direct Rust 1.88 rustfmt was then used successfully. The first data-only decoder check incorrectly treated Glyph's i32 y as f32 and stopped at the full-i32 case; correcting the decoder's type handling made all 26 lists pass without changing oracle or Rust source data.

The font metadata facts are input facts: cmap/glyph IDs, empty records, advance/kern values, table identities and bounded record structure. They do not prove expanded curve-coordinate/raster scratch bounds. The additive font API must retain its explicit trusted bundled-font and bounded preflight limitations. This fixture work does not claim worker text capture, arbitrary font support, shaping, GPU text speed, production browser GPU rendering or completion of the browser goal.
