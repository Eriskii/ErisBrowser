# Worker text capture fixtures

These seven local documents exercise real WorkerClient text display lists through the optional fonts-aware offscreen adapter. Six require GPU admission; the visible rounded-background case requires whole-frame `unsupported-rounded-rectangle` fallback. Existing literal-mask, direct-font and original browser/probe fixtures remain separate and unchanged.

`inventory.json` freezes the HTML, request/frame metadata, required Text runs (exact content, size, RGBA and flags), clip/fixed membership, meaningful drawing-command order, image keys/decoded bytes and expected route. `fixture_inventory.rs` is a data-only typed projection for the checker. All frames are 160×80. The scroll fixture uses document offset `(0,-24)` and viewport offset `(0,0)`; the worker's Render command itself receives only width and height.

The complete captured snapshot must be retained before assumption checks. Unknown, missing, reordered or mismatched observations fail the check; they must not cause source expectations to be changed to match outcomes. No command, image, diagnostic or unsupported operation may be removed before adapter admission or the CPU reference. Scope and benign-rectangle filtering described in the inventory apply only to checking the expected drawing-kind sequence. Text positions, detailed clips, content height, load time and rejection command index are captured observations, not invented numerical goldens.

The pixel reference is original Canvas painting over the exact same captured commands and images, with the same frame/clip/offsets. Its pixels are reference-derived differential results, not independently known font coverage or pixel goldens. A fallback frame has no partial GPU dispatch and remains a full CPU target. Capture and font preparation must finish and all workers/fonts must be dropped before Vulkan; the outer supervisor must grant the existing worker-to-GPU transition only after confirming no adopted descendants survive.

The two-pixel PNG is an exact copy from the frozen original browser fixture. Its independently specified decoded RGBA is red opaque followed by blue alpha128. Only the image-order document references it, twice under one key. All document text, CSS, image inputs and expected semantic observations were authored before any worker capture for this suite. No JavaScript, external network request, new font, worker run, renderer or GPU execution is part of fixture preparation.

The expected source behaviors are based on the current custom layout's tokenizer, inline Text/Line emission, CSS paint grouping, overflow scopes, fixed-coordinate scopes and image command paths. They are assumptions that the later real worker capture must verify. This suite does not establish general CSS/text conformance, independent glyph rasterization accuracy, production browser GPU rendering or a performance result.
