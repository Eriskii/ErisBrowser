# Pinned Unicode identifier data

JavaScript identifier membership uses the official **Unicode 18.0.0**
`ID_Start` and `ID_Continue` binary properties, with ECMAScript's additions.
It does not use Rust/Python alphabetic predicates, XID properties, normalization,
case folding, or a restricted identifier-security profile.

The private generated module exposes:

```rust
pub(crate) const IDENTIFIER_LOOKUP_WORK: usize = 2;
pub(crate) fn is_identifier_start(value: char) -> bool;
pub(crate) fn is_identifier_part(value: char) -> bool;
```

Start accepts `ID_Start`, `$`, and `_`. Part accepts `ID_Continue`, `$`, U+200C
and U+200D. Underscore and both join controls are already present in the pinned
`ID_Continue` data; the join-control additions remain explicit in the predicate.
Rust `char` inputs are scalar values, so no surrogate code point can enter these
APIs. Escape parsing and contextual keyword checks belong to the separate
parser implementation. These predicates do not establish complete ECMAScript
lexical or Unicode conformance.

The rules follow [ECMAScript identifier names](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-names-and-keywords).
The source format is documented by [Unicode UAX #44](https://www.unicode.org/reports/tr44/#DerivedCoreProperties.txt);
[UAX #31](https://www.unicode.org/reports/tr31/) distinguishes ID from the
normalization-related XID properties. U+037A is one tested ID/XID distinction.

## Deterministic bounded generation

```sh
python3 tools/generate_js_identifiers.py
python3 tools/generate_js_identifiers.py --check
python3 -m unittest discover -s tools -p 'test_generate_js_identifiers.py'
```

The standard-library-only generator is **always offline**, including its default
mode. It reads the pinned local files and writes only the generated module.
`--check` verifies exact generated bytes without rewriting the output. Optional
`--data-dir` and `--output` paths support isolated verification; they do not
relax any provenance or table validation. Output cannot alias an input file.
A Unicode update requires an explicit pin, evidence, table and test review.

Input verification happens before generation. Files are bounded at 2 MiB each,
the manifest at 16 KiB, derived data at 20,000 lines and 1,024 characters per
line. Symlink inputs are rejected. Selected property sections must occur exactly
once with matching version/date, exact property names, valid scalar ranges,
strict source order, no overlaps or surrogates, and matching record and section
counts. Records outside their section, after its total, or with malformed
selected syntax are rejected. `ID_Start` must be a subset of `ID_Continue`.

The parser allows at most 4,096 raw records and 2,048 merged ranges per property;
output is capped at 256 KiB. Adjacent ranges merge deterministically for
validation before packing, without changing membership or truncating records.
The validated property statistics are:

| Property | Code points | Source records | Merged inclusive ranges |
| --- | ---: | ---: | ---: |
| ID_Start | 158,739 | 789 | 695 |
| ID_Continue | 162,100 | 1,437 | 814 |

The generated representation covers the fixed domain U+0000..U+10FFFF with
**4,352 one-byte page IDs**. Each page covers **256 code points**, with two bits
per code point: ID_Start first, then ID_Continue. The **132 unique pages** each
contain eight u64 words (64 bytes). Duplicate pages receive the ID assigned at
their first occurrence while scanning the domain in ascending order. Total
static payload is **12,800 bytes**: 4,352 index bytes plus 8,448 bitmap bytes.

Generation uses a fixed 278,528-byte intermediate bitmap. It rejects more than
256 unique pages, invalid page dimensions or page IDs, and any failure to cover
the fixed scalar domain. These limits bound the static representation at
20,736 payload bytes even if a future reviewed data pin contains more distinct
pages. Bits for surrogates and nonmembers remain zero; no property range is
truncated to make it fit.

ASCII retains a fixed fast path. Other lookups read one page ID and one bitmap
word, followed by fixed shifts and masks. There is **no lookup loop, allocation,
normalization, cache mutation or runtime database access**. The private
`IDENTIFIER_LOOKUP_WORK = 2` constant records these two bounded table reads so
compiler accounting follows the actual representation. The parser still owns
all separate scanning, decoding, copying and storage charges; this table change
does not raise any source/work/storage quota.

The first implementation used binary-searched ranges with 12,072 payload bytes.
Replacing it with packed pages adds 728 payload bytes and removes repeated
search probes. Its frozen generator/module/tests remain preserved in
`/tmp/eris-identifiers-preliminary`; both representations have the same exact
pinned membership and were independently checked for every scalar. The
[preliminary profile report](test262-identifiers-preliminary.json) preserves the
resource outcomes that motivated reviewing actual lookup work.

The generated source is **46,224 bytes**, including license, APIs and tests,
with SHA-256
`49187f73fcbae9d685e7848c6a412315c247a7fbfd4f3919bd5c08f8a6a7b552`.

## Verification evidence

**Eleven Python tests** pass. They cover byte corruption in every pinned file,
manifest/data repinning attempts, URL/inventory/final-status/retrieval tampering,
symlink and size limits, malformed/overlapping/out-of-order/non-scalar records,
wrong totals/version/section placement, range/page/output caps, deterministic
first-use deduplication, fixed page/index dimensions, rendering, preservation of the complete license, and read-only stale-output
checks. A separate straightforward record parser expands membership bitmaps and
compares every code point with independently decoded generated bitmap literals.
It does not call the generator's section parser, merge or packing logic, or use
host Unicode predicates.

The generated module also has **two standalone Rust tests**, runnable without
building the parser:

```sh
rustc --edition 2024 -D warnings --test src/js_identifier.rs -o /tmp/eris-identifier-tests
/tmp/eris-identifier-tests
```

The exhaustive test independently reads the original semicolon property records,
checks their totals, then invokes the actual Rust predicates for **all 1,112,064
Unicode scalar values**. It passed for both predicates. Focused checks cover
ASCII additions, ID/XID distinctions, combining marks, continuation digits,
connector punctuation, join controls, supplementary letters and rejected
superscripts/emoji/BOM/noncharacters. The Python bitmap test also includes the
pinned classifications of U+0558, U+05C8, Jurchen and Small Seal endpoints.
U+05C8 is continuation-only, rather than an identifier start.

Standalone strict compilation, rustfmt check and deterministic generator
`--check` pass. This data checkpoint does not modify any Test262 corpus,
profile, execution policy or baseline.
