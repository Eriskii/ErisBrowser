# Inline CSS declaration storage and bindings

This is a bounded, partial implementation of inline `CSSStyleDeclaration`, not a CSSOM conformance claim. The storage/parser is `src/cssom.rs`; the host bindings are in `src/script.rs`. It reuses the engine's component-token cursor, custom-value validation, shorthand expansion, and strict supported value helpers. It does not change the positive inventory reported by `CSS.supports`.

## Sources and algorithms

The implementation was checked against the current [CSSOM declaration-block interface](https://drafts.csswg.org/cssom/#the-cssstyledeclaration-interface), [CSSOM value serialization](https://drafts.csswg.org/cssom/#serializing-css-values), [CSS Syntax declaration consumption](https://www.w3.org/TR/css-syntax-3/#consume-a-declaration), [component-value consumption](https://www.w3.org/TR/css-syntax-3/#consume-a-component-value), and [CSS Syntax serialization token boundaries](https://www.w3.org/TR/css-syntax-3/#serialization), accessed 2026-09-28. These are live specifications; the tests here are self-authored and are not imported WPT results.

The parser separates declarations only at top-level semicolon tokens. Strings, URLs, nested functions/simple blocks, escapes and comments cannot introduce another property. A declaration name must be one identifier token followed by a colon. A final top-level `!` plus an ASCII-insensitive `important` identifier is stored separately from its value. Invalid declarations are omitted when parsing a declaration block. Unknown ordinary properties are omitted. A setter validates its complete standalone value and priority before editing the staged record list; malformed values, injected declarations, and invalid priorities leave the original DOM attribute unchanged.

Ordinary method names are ASCII-insensitive literal CSS names. They are not trimmed, CSS-unescaped, or converted from camelCase. Custom names preserve case. Source identifier escapes are decoded into name identity, while API backslashes remain literal characters. Serialization escapes punctuation, control characters and backslashes in custom names, so a literal name containing a colon, semicolon, braces, or comment opener cannot introduce CSS syntax. Empty `--` and NUL-containing names are rejected in this subset. Values are trimmed by whitespace **token spans**, preserving escaped trailing space and hex-escape terminators within identifiers.

EOF repair is deliberately limited: unmatched string/function/block/URL endings and odd trailing escape parity are rejected. A URL with an escaped apparent closing parenthesis is also rejected. EOF comments are discarded rather than retained across a serialized declaration separator. The parser does not implement general CSS error-repair serialization, nested declaration rules, or arbitrary unknown at-rules.

## Retained values and mutation behavior

The ordinary property-name inventory comes from the renderer's supported longhands and shorthand expander. Recognized values use a strict subset of those grammars: CSS-wide keywords; implemented display/position/float/clear/box-sizing keywords; supported lengths and percentages; finite opacity/flex numbers and integer order/z-index; supported colors; font family lists, font size/style/weight/line-height; text alignment/white-space/simple decoration; supported flex/grid alignment, tracks/lines/auto-flow; overflow, simple border radius, list markers and vertical alignment. This is not the complete standards grammar for these properties. For example, background accepts a single supported color, decoration accepts the implemented line keywords, radius accepts one to four nonnegative lengths/percentages, and unsupported font variations, background images and advanced math functions are rejected.

Length arithmetic preserves nested `calc()` sums/differences, validates required operator whitespace, and rejects token-joining such as an escaped identifier becoming a dimension. Mixed-unit expressions such as `calc(100% - 10px)` are retained as syntactically valid declarations; the renderer still cannot resolve every mixed-unit expression. Retention must not be interpreted as newly implemented layout behavior.

Literal shorthands expand through the renderer and validate every emitted longhand atomically. Supported forms include physical/logical margin and padding, inset, border widths/styles/colors and side borders, single-color background, flex/flex-flow, the existing font subset, gap/grid-gap, Grid line/area, place-* alignment, and list-style. `all` supports CSS-wide or pending values. Renderer aliases such as inline-size/block-size, physical mappings of logical edge names, grid-row-gap/grid-column-gap and text-decoration-line remain the renderer's existing partial mappings. Writing-mode-dependent logical mapping is not implemented.

Existing supported authored font, quoted family, border, flex, Grid and calculated-length values survive unrelated mutation. Declaration order and priority determine the retained winner; setting a property replaces its existing priority, and removing it does not resurrect an earlier duplicate. Existing ordinary records retain their index when replaced. Empty setter values remove the property before priority validation, as CSSOM specifies. Custom empty/whitespace values parsed from authored text remain distinguishable from absence through record existence/priority, although their value query is empty.

Pending `var()` shorthands retain their original shorthand record and source position. Unrelated edits, whole-shorthand edits/removal, and representable later longhand overrides are supported. For example, `margin:var(--m)` followed by `setProperty('margin-top','10px')` keeps the other sides pending. An important pending shorthand can be partially overridden by a later important longhand. Partial removal, or lowering a pending important side to normal priority, cannot in general be faithfully represented by this textual storage model; those ambiguous operations leave the entire declaration block unchanged. An unsupported partial removal returns an empty string. This is an explicit remaining CSSOM limitation.

`getPropertyValue` returns a winning longhand value or reconstructs the implemented simple shorthand forms only when all constituent winners exist and share a priority. A complete pending shorthand can return its authored pending value; a pending constituent longhand returns the empty string. Full `font` and `all` reconstruction is absent except common CSS-wide values. Serialization generally emits expanded longhands, retains raw custom/pending tokens, and does not canonicalize every color, unit, escape or shorthand according to full CSSOM rules. Pending records count as one entry in this partial storage model, so their `length`/indexed enumeration does not claim the standard's complete pending-longhand representation.

## Host binding subset

Inline `element.style` supports `cssText`, `length`, `item(index)`, numeric indexed reads, `parentRule` (`null`), `getPropertyValue`, `getPropertyPriority`, `setProperty`, and `removeProperty`. Recognized ordinary properties have exact canonical camelCase and dashed aliases plus `cssFloat`/`float`; custom properties use the methods. Unknown reflected properties are absent instead of pretending to be implemented CSS.

Methods use dynamic receiver brand checks and required-argument checks. Author string-hint conversions finish in argument order before the current style attribute is read. The CSSOM string boundary uses USVString conversion. Reflected property setter values and `setProperty` value/priority use the specified null-to-empty conversion; `cssText` uses ordinary string conversion. Reentrant conversions therefore cannot be overwritten by a stale declaration snapshot. A complete detached parse, mutation and serialization succeeds before the binding makes one DOM write. Resource failures are uncatchable runtime errors and do not commit a partial style attribute.

Expando properties, replacing methods, full CSSStyleDeclaration prototype/descriptor/own-key behavior, computed styles, stylesheet rule declarations, and complete shorthand serialization remain outside this slice. Generic JavaScript computed-property-key timing is tested separately in the runtime.

## Bounds and checks

- Inline input and serialized storage: 64 KiB each, with escaped name bytes included in the output ledger.
- Stored declarations: at most 256; individual values: at most 4 KiB; decoded/literal names: at most 256 bytes.
- Component nesting: at most 16; shared tokenizer inventory: at most 16,384 tokens.
- All scans, comparisons, recursive arithmetic checks, expansion and copies spend the caller's shared work budget. Exhaustion sets remaining work to zero and aborts; it is not negated into a successful validation result. Recursive arithmetic scans borrowed components instead of allocating another complete token vector per nesting level.
- The runtime precharges the helper's conservative cumulative scratch allowance, `512 * (source and argument UTF-8 bytes) + 32 KiB`, before parsing/copying. Existing script-entry work and heap limits still apply. Structural source/value/storage/inventory limits abort without a DOM commit.

Eight CSSOM unit groups cover nested/quoted delimiters and recovery; custom-name case/escaping/injection; priorities, empty values and atomic removal; literal shorthand winner ordering; pending shorthand safe/unsupported overlaps; preservation and strict malformed-value rejection; resource limits and recursive-work exhaustion; and EOF/escaped-whitespace/URL serialization boundaries. Script tests cover the binding subset, conversions, reentrancy, shared methods/brands, aliases/indexes, and resource nonmutation. Root-owned pipeline and real-worker fixtures exercise visible priority/custom-name/quoted-value/edit behavior. Independent scratch probes cover renderer-state preservation, malformed mutations and decoded-name/value injection; these are safety checks, not a wider conformance score.
