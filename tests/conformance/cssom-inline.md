# Inline CSS declaration storage and bindings

This is a bounded, partial implementation of inline `CSSStyleDeclaration`, not a CSSOM conformance claim. The storage/parser is `src/cssom.rs`; the host bindings are in `src/script.rs`. It reuses the engine's component-token cursor, custom-value validation, shorthand expansion, and strict supported value helpers. It does not change the positive inventory reported by `CSS.supports`.

## Sources and algorithms

The implementation was checked against the current [CSSOM declaration-block interface](https://drafts.csswg.org/cssom/#the-cssstyledeclaration-interface), [CSSOM value serialization](https://drafts.csswg.org/cssom/#serializing-css-values), [CSS Syntax declaration consumption](https://www.w3.org/TR/css-syntax-3/#consume-a-declaration), [component-value consumption](https://www.w3.org/TR/css-syntax-3/#consume-a-component-value), and [CSS Syntax serialization token boundaries](https://www.w3.org/TR/css-syntax-3/#serialization), accessed 2026-09-28. These are live specifications; the tests here are self-authored and are not imported WPT results.

The parser separates declarations only at top-level semicolon tokens. Strings, URLs, nested functions/simple blocks, escapes and comments cannot introduce another property. A declaration name must be one identifier token followed by a colon. A final top-level `!` plus an ASCII-insensitive `important` identifier is stored separately from its value. Invalid declarations are omitted when parsing a declaration block. Unknown ordinary properties are omitted. A setter validates its complete standalone value and priority before editing the staged record list; malformed values, injected declarations, and invalid priorities leave the original DOM attribute unchanged.

Ordinary method names are ASCII-insensitive literal CSS names. They are not trimmed, CSS-unescaped, or converted from camelCase. Custom names preserve case. Source identifier escapes are decoded into name identity, while API backslashes remain literal characters. Serialization escapes punctuation, control characters and backslashes in custom names, so a literal name containing a colon, semicolon, braces, or comment opener cannot introduce CSS syntax. Empty `--` and NUL-containing names are rejected in this subset. Values are trimmed by whitespace **token spans**, preserving escaped trailing space and hex-escape terminators within identifiers.

EOF repair is deliberately limited: unmatched string/function/block/URL endings and odd trailing escape parity are rejected. A URL with an escaped apparent closing parenthesis is also rejected. EOF comments are discarded rather than retained across a serialized declaration separator. The parser does not implement general CSS error-repair serialization, nested declaration rules, or arbitrary unknown at-rules.

## Retained values and mutation behavior

The ordinary property-name inventory comes from the renderer's supported longhands and shorthand expander. Recognized values use a strict subset of those grammars: CSS-wide keywords; implemented display/position/float/clear/box-sizing keywords; supported lengths and percentages; finite opacity/flex numbers and integer order/z-index; supported colors; font family lists, font size/style/weight/line-height; text alignment/white-space/simple decoration; supported flex/grid alignment, tracks/lines/auto-flow; overflow, simple border radius, list markers and vertical alignment. This is not the complete standards grammar for these properties. For example, background supports the bounded image/color and geometry subset documented in [layered backgrounds](../../docs/background-layers.md), decoration accepts the implemented line keywords, and radius accepts one to four nonnegative lengths/percentages. Unsupported font variations, image functions and advanced math functions are rejected.

Length arithmetic shares the renderer's typed additive `calc()` parser, preserving nested sums/differences, required operator whitespace and escape boundaries. Mixed length-percentage values retain coefficients until the applicable containing-block basis is available. The [calculation scope](calc-lengths.md) documents supported layout consumers, clamping, intrinsic contexts and remaining mathematical-function limitations. CSSOM retention alone does not establish complete layout support for a property.

Literal shorthands expand through the renderer and validate every emitted longhand atomically. Supported forms include physical/logical margin and padding, inset, border widths/styles/colors and side borders, the supported seven-longhand background subset, flex/flex-flow, the existing font subset, gap/grid-gap, Grid line/area, place-* alignment, and list-style. `all` supports CSS-wide or pending values. Renderer aliases such as inline-size/block-size, physical mappings of logical edge names, grid-row-gap/grid-column-gap and text-decoration-line remain the renderer's existing partial mappings. Writing-mode-dependent logical mapping is not implemented.

Existing supported authored font, quoted family, border, flex, Grid and calculated-length values survive unrelated mutation. Declaration order and priority determine the retained winner; setting a property replaces its existing priority, and removing it does not resurrect an earlier duplicate. Existing ordinary records retain their index when replaced. Empty setter values remove the property before priority validation, as CSSOM specifies. Custom empty/whitespace values parsed from authored text remain distinguishable from absence through record existence/priority, although their value query is empty.

Pending `var()` shorthands retain ordered constituent longhand records sharing their original shorthand and source tokens. Replacing one side changes that side and its priority; removing it deletes only that side, even when its public value is empty. Other sides retain their pending values and respond to later custom-property changes. The document retains this state across script entries, layout and worker renders. A complete group can serialize as its original shorthand; a partial group emits empty-valued pending longhands. Replacing the attribute externally, or assigning its serialized text back through `cssText`, reparses the text and loses those unobservable pending values. See [persistent pending declarations](../../docs/cssom-pending.md) for ownership, serialization and snapshot boundaries.

`getPropertyValue` returns a winning longhand value or reconstructs the implemented simple shorthand forms only when all constituent winners exist and share a priority. A complete pending shorthand can return its authored pending value; a pending constituent longhand returns the empty string. Ordinary non-pending `font` and `all` reconstruction is absent except common CSS-wide values; complete original pending groups can return their source tokens. Serialization generally emits expanded longhands, retains raw custom/pending tokens, and does not canonicalize every color, unit, escape or shorthand according to full CSSOM rules. Pending constituents each count toward `length` and indexed enumeration, including the existing 256-record cap. Complete reconstruction requires matching source content and priority from the same original shorthand; a subshorthand is not relabelled from a larger pending shorthand.

## Host binding subset

Inline `element.style` supports `cssText`, `length`, `item(index)`, numeric indexed reads, `parentRule` (`null`), `getPropertyValue`, `getPropertyPriority`, `setProperty`, and `removeProperty`. Recognized ordinary properties have exact canonical camelCase and dashed aliases plus `cssFloat`/`float`; custom properties use the methods. Unknown reflected properties are absent instead of pretending to be implemented CSS.

Methods use dynamic receiver brand checks and required-argument checks. Author string-hint conversions finish in argument order before the current document-owned style state is read. The CSSOM string boundary uses USVString conversion. Reflected property setter values and `setProperty` value/priority use the specified null-to-empty conversion; `cssText` uses ordinary string conversion. Reentrant conversions therefore cannot be overwritten by a stale declaration snapshot. A complete detached parse or checked clone, mutation and serialization succeeds before the binding publishes the attribute and typed declarations together. Resource failures are uncatchable runtime errors and do not commit a partial style attribute.

Expando properties, replacing methods, full CSSStyleDeclaration prototype/descriptor/own-key behavior, computed styles, stylesheet rule declarations, and complete shorthand serialization remain outside this slice. Generic JavaScript computed-property-key timing is tested separately in the runtime.

## Bounds and checks

- Inline input, conservative logical declaration storage and serialized output: 64 KiB each, with escaped name bytes included in the output ledger.
- Stored declarations: at most 256; individual values: at most 4 KiB; decoded/literal names: at most 256 bytes.
- Component nesting: at most 16; shared tokenizer inventory: at most 16,384 tokens.
- All scans, comparisons, recursive arithmetic checks, expansion and copies spend the caller's shared work budget. Exhaustion sets remaining work to zero and aborts; it is not negated into a successful validation result. Recursive arithmetic scans borrowed components instead of allocating another complete token vector per nesting level.
- The runtime precharges the helper's conservative cumulative scratch allowance, `512 * (source and argument UTF-8 bytes) + 32 KiB`, before parsing/copying. Typed edits and allocating queries use retained logical bytes, including every pending reference, rather than their potentially shorter serialized attribute. Metadata-only borrowed reads do not reserve a complete parser scratch area. Existing script-entry work and heap limits still apply. Structural source/value/storage/inventory limits abort without a DOM commit.

Eight CSSOM unit groups cover nested/quoted delimiters and recovery; custom-name case/escaping/injection; priorities, empty values and atomic removal; literal shorthand winner ordering; pending shorthand overlaps (subsequently extended by the persistent-state checkpoint); preservation and strict malformed-value rejection; resource limits and recursive-work exhaustion; and EOF/escaped-whitespace/URL serialization boundaries. Script tests cover the binding subset, conversions, reentrancy, shared methods/brands, aliases/indexes, and resource nonmutation. Root-owned pipeline and real-worker fixtures exercise visible priority/custom-name/quoted-value/edit behavior. Independent scratch probes cover renderer-state preservation, malformed mutations and decoded-name/value injection; these are safety checks, not a wider conformance score.
