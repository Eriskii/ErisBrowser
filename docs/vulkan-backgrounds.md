# Native raster backgrounds

The Native Vulkan raster path now admits square-corner `BackgroundImage` commands from loaded CSS URL backgrounds. It supports independently repeated axes, positioned and scaled tiles, source alpha, existing isolated opacity groups, clips, scrolling and fixed-coordinate scopes. The [clickable example](../examples/vulkan-backgrounds.html) changes a repeated tile to a single bottom-right tile while preserving the fixed background. The earlier [CSS URL background checkpoint](css-url-backgrounds.md) remains the resource-loading and layout contract.

This increment prepares integer source lookup tables on the CPU and uses the existing GPU image/group-image shaders. It adds no shader UV arithmetic, filtering, tile enumeration or destination-sized raster. Decoding, URL resolution, cache authority and the display-list/worker format are unchanged. Backgrounds add no generated-gradient sources.

The paint rectangle and tile rectangle remain independent. Both receive the active phase's document or fixed offset exactly once, using the established f32 translation order. Clips restrict output without reconstructing or shifting tile phase. Each axis samples at the destination pixel center, subtracts the translated tile origin in f64, applies Euclidean remainder only when that axis repeats, then divides by tile extent before multiplying by source size. The result truncates and clamps to the final texel. This preserves the existing software background sampler, including negative positions, tiny positive periods and rounding at repeat seams. Ordinary `Image` and framebuffer `ScreenImage` keep their separate edge/identity sampling rules.

A nonrepeated axis uses the half-open interval of pixel centers inside its tile. The GPU window also excludes pixels that the software painter's final integer clip would reject. Its stored window can therefore be smaller than the software candidate loop. Fixed scopes restore the caller clip and viewport offset; popping them restores the preceding document coordinates and clip. Each phase starts from its own coordinate state while sharing scene admission.

Every nonzero radius within the geometry bounds retains `unsupported-background-image` whole-scene fallback, including a rounded command hidden by opacity, an empty clip or a missing raster. Invalid/nonfinite/out-of-range geometry has its own refusal. A valid tile must have positive extents even when paint is empty; the software painter can treat an invalid tile as inert, so Native admission is deliberately stricter. Primitive and font-aware Probe bridges continue to refuse all background commands. The dedicated Native checker does not widen those older routes.

Complete command preflight finishes before source or font payload preparation. The adapter then reserves geometry work before constructing source tables. For a nonempty software candidate loop of `P` pixels, its debit is `T = 8 + P * (3 + rx + ry)`. For a nonempty final GPU window of width `W` and height `H`, lookup preparation adds `L = 8 + (3 + rx) * W + (3 + ry) * H`, where `rx` and `ry` are 0 or 1. An absent corresponding window costs zero. Native prepays `T + L` under its existing viewport-derived CPU allowance, `clamp(16 * viewport_area, 1,000,000, 32,000,000)`, shared with other paint preparation. Missing, transparent and suppressed commands retain conservative reservations; these are work tariffs, not measured instruction counts or actual LUT allocations for missing images.

Ordinary images and backgrounds share key accounting, source lookup and allocation-identity deduplication. Every supplied unique raster is validated, including unreferenced entries. Missing keys emit no image draw. A visible `W` by `H` background adds `W + H` 32-bit lookup entries and one parameter record; the original source pixels are packed once per unique allocation. Final core admission precedes table writes and submission.

Limits remain four Native phases, 256 commands, 32 scopes, a 1,280 by 1,024 physical target, 256 combined source entries, 1 MiB aggregate image RGBA, 589,824 lookup entries, 16 MiB GPU buffers and 4,000,000 padded invocations. Background keys share the existing 4,096-byte per-key and 65,536-byte command-key caps. Source, mask, row, target, conversion and opacity storage remain in the existing shared ledgers. Metadata estimates include enlarged command/pending records and the new temporary geometry descriptors; they do not claim to measure all allocator or driver overhead.

Final source validation passed 2,707 tests with Rust 1.88 and `vulkan-raster`, and 2,483 with Rust 1.98 default features. Each complete run had 33 result groups, zero failures and zero ignored tests. Standalone core suites with the `gpu` feature passed 168 tests on each version; probe suites passed 15 on each. The 29 new groups comprise 14 core, 12 adapter and three integration tests, including direct Page and confined-worker click/cache/fixed-scroll checks. Strict Clippy passed for native and core on both versions, and for default/probe on Rust 1.98; all three formatting checks passed. All 76 existing self-authored reference pairs still matched exactly. No candidate check failed after the 595-input compiled source snapshot was frozen.

The dedicated immutable Vulkan checker matched six independent fixtures against Canvas and literal expected pixels on NVIDIA GeForce RTX 4070 SUPER, AMD RADV Raphael and llvmpipe. The fixtures contain 222 pixels and cover repeat modes, fractional geometry, alpha/nested opacity, fixed restoration and the distinction from ordinary image sampling. Each adapter matched both BGRA8 and RGBA8 output: 12 offscreen frames and 1,776 compared bytes, or 36 frames and 5,328 bytes across all three. These checks exercise the custom image shaders; they do not demonstrate acquired-window presentation or an elapsed-time speedup.
