# CSS URL backgrounds

Eris supports one `url()` background image alongside the existing single-gradient alternative. Quoted and unquoted URLs, CSS escapes, custom-property substitution, cascade rollback and explicit inheritance use the shared CSS parser. A background can combine its image with color, size, physical position and repeat controls; the shorthand resets all five supported longhands. Multiple image layers, `image-set()`, `cross-fade()`, `space`/`round` repetition, background attachment and origin/clip controls remain unsupported.

A relative URL resolves against the source of the winning **consuming declaration**. External stylesheets retain their final redirected URL, including imported sheets. Inline styles and document styles use the current document base when styles are computed. Custom properties retain unresolved tokens: a URL inside `var()` uses the declaration that consumes it, rather than the stylesheet that originally declared the variable. Explicit `background-image: inherit` shares the parent's already computed image identity. A later base or CSS mutation affects the next style computation, without changing the resource loader's authority.

Empty, local-fragment and unresolved values remain image values but supply no raster and make no resource request. An unavailable winning image does not reveal an earlier losing declaration. Image presence also controls root/body propagation: an unavailable root image prevents the body's background from becoming the canvas background; the body can still paint its own box. Absolute URLs retain their computed fragment, while fetch/cache identity omits it. Fragment-specific SVG selection is not implemented.

`Page::prepare_layout` is the explicit mutable resource phase. It computes styles once, selects image resources, then passes that same style vector and borrowed loaded-image bindings into layout. `Page::layout` remains read-only: it may paint authenticated cached backgrounds but cannot fetch. Pages constructed by `from_html`, built-in pages and error pages have no retained resource session, so preparation grants them no I/O. Changing an `<img>` source does not gain a new image-loading trigger from this feature.

The worker prepares backgrounds during `Render`, before collecting images and diagnostics for its snapshot. The headless renderer also prepares once before painting. Subsequent timed `--benchmark` iterations recompute styles, perform cache-binding checks, lay out and paint without fetching or decoding; preparation is outside those samples. This extends the warmed asset set for URL-background workloads, so older measurements need matching workloads and preparation before comparison. No timing or GPU-speedup result is claimed here.

Resource selection uses a bounded connected-tree traversal. It skips templates, `display:none` subtrees, hidden inputs and closed disclosure content, with the existing root/body canvas-owner exception. It does not skip a resource merely because its box is offscreen or its eventual tile has zero size. Fetching uses the original retained navigation Fetcher and existing image success/failure cache. Redirect checks, file boundaries, mixed-content rules, CSP handling, response limits and opaque cross-origin decoding stay in those established paths.

The retained bridge Fetcher counts attempts before invoking its captured callback, including failed attempts. After 48 attempts it refuses another honest request locally, before IPC. This supplements the unchanged parent and broker guards; it does not reset their request totals, response bytes, cancellation or deadlines. Direct fetching keeps its original counters and start time, including the 30-second page age. Ordinary image refusals leave unavailable backgrounds and bounded diagnostics. A broker or transport termination can still end the worker exchange.

Loaded pixels are published under private generated ImageStore keys. Prefix spelling alone is insufficient: publication avoids existing aliases, and every layout handoff checks that the published image is the exact cached allocation with valid dimensions and a complete RGBA buffer. Redirect taint travels with that cached image. Layout receives only a borrowed key and decoded width/height, never URL-fetch authority or another raster allocation.

The CSS image pool shares the existing 4 MiB image admission allowance and style-work budget between gradients and URL values; the image allowance includes cumulative URL scratch and reservations. Page preparation has 16,777,216 work units and a separate 16 MiB temporary-metadata admission; each session additionally has 4 MiB cumulative background metadata, the existing 33,554,432 resource-URL work units and at most 48 URL-to-key registrations. Collision repair can leave older aliases in ImageStore; their publications remain charged against cumulative metadata. The existing 64 MiB image limits cover both cumulative external decoding and live unique raster allocations, including cache-only images and SVG output. Failed operations and discarded work do not refund cumulative allowances. These are conservative admission policies, not measurements of all allocator memory or processor instructions.

Layout prepays each key copy against a 4,096-byte per-key ceiling, 65,536 cumulative key bytes and `length + 1` units of existing layout work. Natural raster dimensions determine `auto` sizing and aspect ratio; contain/cover, percentages, calculations and signed free-space positioning use bounded geometry. Canvas backgrounds use the root padding area, inline fragments share a virtual strip, and stretched table/flex/grid boxes use their final geometry. Zero-sized tiles paint nothing. SVG backgrounds use the decoded raster's dimensions, not a complete SVG intrinsic-size model or a fresh vector rendering at every tile size.

Painting uses the existing tiled-raster CPU command, clipping, repeat-axis controls, alpha and opacity handling. Native/probe raster bridges still refuse that command and select whole-frame software fallback; no new GPU image-background admission is added. General nonuniform or translucent rounded-border limitations remain.
